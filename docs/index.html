把企划从「写 46 页 PPT」
改成「按决策问题产出证据链」

AI 负责 数据 → 证据 → 机会 → 候选策略 → 事后验证 的整条产线；人保留两件事——取舍与拍板。这一页讲清整套设计，以及配套的萃取任务书为什么要推倒重写。

「为产品经理快速输出高质量的市场机会清单、本品复盘结论、用户需求结论，统一全团队企划输出标准，大幅降低重复找数与低效分析成本。」 —— 原始需求书的目标句。整套系统就是把这句话做成能跑的东西。

01 / 路线之争

同一份历史资料，两条完全不同的路

路线 A · 萃取 → 教材 → 人执行

把老方法整理成方法论文档 / SOP，教给下一个人

产物是给人读的报告。方法要写到人能学会，每换一个产品经理重新教一遍；找数、做表、验证仍然靠人力。

路线 B · 萃取 → 系统 → AI 执行

把事实层和闭环建给 AI，方法固化进系统

方法写进十个决策问题和规则卡就固化了，换人不影响执行；找数、分析、初稿、追问全自动，人只审结论、做取舍。

本仓库按路线 B 建造，但路线 A 的萃取成果没有浪费——它是系统的冷启动物料：9 张规则卡、10 条口径案例、260 行结构化历史数据，全部萃取自五季历史企划案。萃取从「一次性写教材」变成了「持续给系统喂料」。

02 / 系统结构

四层结构，能少则少

事实层
data/inbox → SQLite → 冻结快照 → 口径手册
每周 CSV 导出入库；答题只引用带 ID 的冻结快照，每个数字可复算。功夫的大头在这一层。
知识层
规则卡 + 策略预测台账
规则只收两种来源：评审会拍板、预测被验证。每季新增 ≤10 张，失效即删。
产出层
十个固定决策问题 → 一页简报
按决策问题组织工作，不按 PPT 章节组织。每问固定 输入 / 方法 / 输出 / 闸门。
交付层
简报包 + 策略候选卡 + 随时追问
PM 的工作从「做分析」变成「审结论、做取舍」；对任何数字可以追问「怎么算的」，AI 基于同一快照现查现答。
闭环：每条被采纳的策略必须带一条可检验预测 → 登记预测台账 → 下季 Q1 自动对账 → 验证成立的规律沉淀为规则卡

十问对应的正是需求书里的三类输出

结论（节选）

200-300 带防守成功：份额 25.5%→30.2%，两季段内第一 [S-20260824 份额表]。300-400 带名义第一但被追击：本品 25.6%→24.8%，第二名 15.9%→22.7%，差距从 9.7pp 收窄到 2.1pp [S-20260824 份额表]。400-500 带实质失守：1.9%→0.12% [S-20260824 份额表]。

反方（模板强制，不许空）
  • 两季金额单位不一致（一季用元、一季用万元），跨季对比可能失真——这个坑就是产线自己抓出来的，已进口径手册；
  • 「失守」也可能是主动收缩，与战略放弃在数据上同形，需新数据定性。

最关键的一幕：AI 编数字，出不了稿

给校验闸喂三份故意写坏的稿子——数字没带引用、样本量不够没标线索、策略卡缺字段、规则卡来源乱写——当场全部抓出：

$ python3 scripts/check_brief.py briefs/_t R-888888-1.md: R1 来源非枚举值: 我觉得对 brief-bad.md:6 B5 样本量 N<200 未标「线索」: 问卷 N=82 显示37%要直筒 card-bad.md: B4 缺字段行: 验证方式 / 定价与价格带落位 … 检查 3 个文件，8 处违规 → exit 1，不出稿 ——同一把闸对正规稿：检查 10 个文件，0 处违规 → 放行
04 / 纪律

fail closed：宁可说不知道，不许编

引用强制

简报中每个数字必须带 [S-快照 表名] 引用，机器校验，缺引用不出稿。

样本红线

占比类 N≥200、立项类 N≥300 且含未购人群配额；不达线一律降级「线索」，线索不得支撑策略。

缺口明说

快照里没有的数据，写「缺口：缺什么、从哪导」，禁止补写、禁止猜。

人签底线

立项与订货金额永远只是建议，落款「待人签」；分析全自动，拍板永远在人。

05 / 任务书重写

萃取提示词为什么要推倒重写

原版提示词把萃取定义成「写一份报告」。报告的结构、粒度、列名由模型现场发挥——喂不同资料、甚至同资料跑两次，产出结构都会漂移，无法比对、无法合并、无法入库。

重写版把任务重新定义为「按固定 schema 抽取记录」：结构不再由模型决定，由任务书决定。给 AI 的文档只该有四类内容——纪律、规格、任务定义、事实；判据一句话：删掉这句话，模型行为会不会变？不变，它就是给人的，分流去人类文档。

① 记录 SCHEMA

方法 / 规则 / 口径 / 事实四类记录逐字段定义，字段顺序、空值写法全部写死。

② 固定词表

所有分类字段只许用枚举值，自创值＝违规；装不进词表的进备注并上报。

③ 判定规则

粒度、跨文档合并、口径冲突、图片页、转引、字段漂移——每个裁量点都有判据。

④ 自检闸

六条机器式检查（计数、字段、溯源、冲突、绑定、逐页覆盖），任一不过不得交付。

#原版的问题重写版的解法
0报告式交付，结构靠模型发挥，每次漂移记录抽取：schema + 词表 + 固定产出文件清单
1萃取物不分类，全进一张大表四类记录各有 schema，分别流向任务清单 / 规则卡 / 口径手册 / 数据快照
2「原文未标注」只标注、不收口《待拍板清单》成为固定产出，直接当评审会议程
5口径冲突静默取其一《口径冲突表》强制并列（实锤案例：金额单位元 vs 万元）
8无验收方式，质量不可检查六条自检，任一不过＝本次萃取不验收
9一次性任务，新文档来了重做全量增量模式：记录 ID 稳定，只交付新增与变更

任务书全文与 12 点对照：docs/提示词优化/。诚实边界：提示词能钉死结构，字段内文字仍有微差；彻底钉死靠产出后的机器校验器（与本仓 check_brief 同款思路）。

06 / 落地

三步走，最小闭环起步

  1. 事实层最小版 + 两个问题（2–4 周见效）：定每周导出清单 → 首个真实快照 → 答 Q2 调换稳杀 + Q7 抱怨 Top3。验收标准：PM 不再为这两件事手工找数。
  2. 外部数据 + 机会清单：竞品 SKU 打标、评论与退货原声结构化 → 答 Q3–Q9，产出第一份机会清单与策略候选集。
  3. 预测闭环：评审采纳的策略全部登记预测台账 → 下季复盘自动生成。验收标准：复盘不再从零写。

启动前需要拍板的事

  • 口径手册 10 条草案的「待拍板」点逐条定死（退货率按件还是按金额、新客怎么定义……）
  • 9 张种子规则卡首次评审：转正或删
  • 指定每周导数责任人与导出清单
  • 定价决策是否归企划（决定 PSM / 联合分析是否启用）
  • 《27春企划案》原件补齐

明确不建的东西：多 agent 编排、自动评分系统、自动订货、审批流。一个模型 + SQLite + 固定问题清单；复杂度只允许出现在数据质量上。
