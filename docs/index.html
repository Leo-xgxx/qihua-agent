01 / 整套设计

两个立场判断，推出全部设计

判断一

AI 的位置不是「写那份 PPT」

PPT 是给评审会看的叙事外壳；工作的本体是回答十几个固定的决策问题。按章节组织（看复盘/看大盘/看市场…）是给人读的方式，按决策问题组织才是给决策用的方式。

判断二

最贵的痛点靠文档解决不了

找数耗人力、需求验证薄弱，这两个最贵的痛点靠「方法论 SOP 教新人」解决不了，靠数据工程 + AI 能解决。功夫的 80% 在事实层，不在提示词。

1.1路线之争：同一份历史资料，两条路

路线 A · 萃取 → 教材 → 人执行

把老方法整理成 SOP，教给下一个人

产物是给人读的报告；每换一个产品经理重新教一遍，找数、做表、验证仍靠人力。

路线 B · 萃取 → 系统 → AI 执行

把事实层和闭环建给 AI

方法固化进十问和规则卡，换人不影响执行；分析、初稿、追问全自动，人只审结论、做取舍。

本系统按路线 B 建造，但路线 A 的萃取成果没有浪费——它是冷启动物料：9 张规则卡、10 条口径案例、260 行结构化历史数据，全部萃取自五季历史企划案。萃取从「一次性写教材」变成「持续给系统喂料」。

1.2四层结构（能少则少）

事实层
data/inbox → SQLite → 冻结快照 → 口径手册
每周 CSV 入库；答题只引用带 ID 的冻结快照，每个数字可复算。AI 在这层做它最擅长的活：竞品打标、评论结构化、退货编码——把非结构化市场信息变成可查询的事实。
知识层
规则卡 + 策略预测台账
规则常态只收两种来源：评审会拍板、预测被验证；每季新增 ≤10 张，失效即删。刻意做小——不是方法论文档，是少量带失效条件的判断规则。
产出层
十个固定决策问题 → 一页简报
企划季启动，AI 对每问跑一遍，产出统一格式简报：结论 / 证据 / 反方 / 待验证假设 / 置信度与缺口。
交付层
简报包 + 策略候选卡 + 评审渲染 + 随时追问
PM 的工作从「做分析」变成「审结论、做取舍」。
闭环：每条被采纳的策略必须带一条可检验预测 → 登记预测台账 → 下季 Q1 自动对账 → 验证成立的规律沉淀为规则卡

对应关系：市场机会清单 = Q9；本品复盘结论 = Q1+Q2；用户需求结论 = Q7+Q8——正好是需求书要的三类输出。另有 8 个行业对标方法（KANO / PSM / 联合分析 / JTBD / AB 测试…）登记在册、按需启用，不做方法货架。

1.4「AI 做策略」的具体做法

策略 = 机会 × 打法 × 资源承诺。AI 不自由发挥，走三步：① 从机会清单出发，每个机会生成 2–3 个候选打法（必须含「不做」选项）；② 每个候选强制填六字段——目标金额（附测算公式）/ 可证伪假设 / 资源要价 / 主要风险与反方论证 / 验证方式 / 定价与价格带落位；③ AI 先自己找证据反驳自己，再交人取舍。

全系统最关键的一条纪律：每条被采纳的策略必须带一条可检验预测。例：「直筒版上市 8 周内拿到该系列销量 20%±5%，否则停止追单」。这一条同时买到三样东西：策略从形容词变成数字；下季复盘全自动生成；预测被验证的规律自动沉淀成规则卡。闭环靠它转。

02 / 仓库结构

仓库本身就是接口：四层各有其位

2.1铁律 13 条（CLAUDE.md，给 AI 的全部行为约束）

取数 1–4

只查冻结快照，禁止用记忆里的行业数字；每个数字带 [S-快照 表名] 引用；指标一律按口径手册算，没口径先建条目；快照没有的数据写「缺口」，不猜不补。

结论分级 5–6

样本量红线分级（占比 N≥200 / 评分对比 ≥300 / 立项闸门 ≥300 且含未购配额），不达线降级「线索」；结论三态——事实（默认）/ 推断（句尾 ⟨推断⟩，引用义务不变）/ 假设（只进待验证段）。

产出 7–10

一题一页入 briefs/<季>/；策略卡六字段缺一不可且必带可检验预测；采纳的策略登记预测台账；立项/订货金额永远「待人签」。

知识层与风格 11–13

规则卡来源三枚举、每季 ≤10 张、失效即删；答题前全量读规则卡；语言直白不用隐喻行话，每页必须有反方段。

证据
  • 200-300：龙牙 25.5%（26春企划）→ 30.2%（26秋冬企划），均列段内第一 [S-20260824 份额表]
  • 300-400：龙牙 25.6%→24.8%；第二名镖王保罗 15.9%→22.7% [S-20260824 份额表]
  • 400-500：龙牙 1.9%→0.12%；九牧王 18.4%→25.12% [S-20260824 份额表]
  • 500-600：仅 26春企划有表，龙牙 3.1%（表内第六）；保罗美思得 20.3% 居首 [S-20260824 份额表]

反方
  • 两季统计窗口与渠道口径原文未标注，且金额单位不一致（26春=元、26秋冬=万元），跨季对比可能失真；「春→秋冬」变化也可能只是季节结构差异，不能直接定性为竞品抢份额。

待验证假设
  • 镖王保罗在 300-400 的追击可持续（验证：新导出近 12 周同段份额周序列，同比+环比双口径）

置信度：低（历史窗口、口径未标注、单位不一致）。缺口：需新导出各段份额（统一单位与窗口、标注渠道）；100-200 段本品份额；500-600 段秋冬数据。

06 / 提示词优化

知识萃取任务书：为什么推倒重写

原版提示词把萃取定义成「写一份报告」（角色设定 + 背景痛点 + 六个交付物）。报告的结构、粒度、列名由模型现场发挥——喂不同资料、甚至同资料跑两次，产出结构都会漂移：无法比对、无法合并、无法入库。

两条修订原则先立住：① 给 AI 的文档只该有四类内容——纪律、规格、任务定义、事实；判据一句话：删掉这句话，模型行为会不会变？不变，它就是给人的，分流去人类文档（所以背景与痛点叙事整段移出，压成两行取舍标准）。② 结构不能由模型决定，由任务书决定——任务从「写报告」重定义为「按固定 schema 抽取记录」。

6.1重写版的九节结构

节内容性质
§0任务与取舍：三类输出定取舍、双使用者（新人 PM + AI）定质量标准任务定义
§1输入清单核对：缺一即停，不得跳过继续纪律
§2固定产出清单：00-处理日志 ～ 07-统计与自检，共 8 件，禁止增删规格
§3四类记录 schema：方法 M-### / 规则 R-### / 口径 K-### / 事实 CSV，逐字段定义规格
§4固定词表：所有分类字段只许用枚举值，自创值＝违规规格
§5处理流程八步，顺序固定任务定义
§6判定规则：粒度、跨文档合并、口径冲突、图片页、转引、字段漂移——每个裁量点给判据纪律
§7增量模式：记录 ID 稳定，只交付新增与变更规格
§8自检六条：计数、字段、溯源、冲突、绑定、逐页覆盖——任一不过不得交付闸门
§9严格性条款：禁自创文件/列/枚举，数字原样照抄，禁在记录里发表评论纪律

6.2记录 schema 长这样（方法记录示例）

ID: M-### ← 编号规则固定：模块词表序 → 首现文档序 → 页码 名称: ≤20字，动宾结构 模块: 看复盘|看大盘|看市场|看用户|看策略 ← 枚举，自创值=违规 目标输出: 机会清单|复盘结论|需求结论（至少一项） 输入数据: 数据源+字段；缺则写「原文未标注」 ← 空值写法也是词表的一部分 操作步骤: 编号列表，每步一句 判断标准: 阈值/公式；缺则「原文未标注」 产出物: 表/图/结论的具体形态 复用分级: ★|◆|○（★=≥3份文档且有产出证据） 完整性: 完整|不完整（五要素缺任一即「不完整」） 失效条件: …；无则「未定义」 溯源: 《文件全称》第X页；转引标「转引自：」

6.3原版问题 → 重写版解法（12 条全量对照）

#原版的问题重写版的解法
0报告式交付，结构靠模型发挥，每次漂移记录抽取：schema + 词表 + 固定产出文件清单
1萃取物不分类，全进一张大表四类记录各有 schema，分别流向 任务清单 / 规则卡 / 口径手册 / 数据快照
2「原文未标注」只标注、不收口《待拍板清单》成为固定产出，直接当评审会议程
3对标方法只要求「引入」，无绑定约束三项绑定硬约束：诊断缺口编号 + 使用场景 + 启用前置条件，缺一不得入表
4无转引规则引用不在手头的文档必须标「转引自：」，不得伪装直接溯源
5口径冲突静默取其一《口径冲突表》强制并列（实锤案例：金额单位 元 vs 万元）
6无字段漂移处理标准名取并集 + 漂移映射入备注（实锤案例：复盘卡维度名各季不同）
7表格数据只转述不抽取《结构化数据表》强制 CSV 长表、逐行带文档+页码（实践：260 行已验证可行）
8无验收方式，萃取质量不可检查六条自检，任一不过＝本次萃取不验收
9一次性任务，新文档来了重做全量增量模式：记录 ID 稳定，只交付新增与变更
10背景与痛点叙事写进 prompt叙事是给人对齐的立项故事，对模型是弱信号且易引偏；压成两行取舍标准，完整背景留人类文档
11成果属性是四个形容词形容词改变不了行为：逐条翻译成可检查条款（入库去向 / 抽卡实测 / 机器可校验 / 五要素齐全）

07 / 落地

三步走，最小闭环起步

  1. 事实层最小版 + 两个问题（2–4 周见效）：定每周导出清单 → 首个真实快照 → 答 Q2 调换稳杀 + Q7 抱怨 Top3。验收：PM 不再为这两件事手工找数。
  2. 外部数据 + 机会清单：竞品 SKU 打标、评论与退货原声结构化 → 答 Q3–Q9，产出第一份机会清单与策略候选集。
  3. 预测闭环：评审采纳的策略全部登记预测台账 → 下季复盘自动生成。验收：复盘不再从零写。

7.1启动前需要拍板的事

  • 口径手册 10 条草案的「待拍板」点逐条定死（退货率按件还是按金额、新客怎么定义……）
  • 9 张种子规则卡首次评审：转正或删
  • 指定每周导数责任人与导出清单
  • 定价决策是否归企划（决定 PSM / 联合分析是否启用）
  • 《27春企划案》原件补齐

明确不建的东西：多 agent 编排、自动评分系统、自动订货、审批流。一个模型 + SQLite + 固定问题清单；复杂度只允许出现在数据质量上。
