# 接入运行手册（给接手的团队和他们的 AI）

## 0. 核心观念：仓库本身就是接口

本系统没有服务、没有 API、不需要部署。"接入协议"就是文件约定：

| 给 AI 的东西 | 在哪 | 怎么用 |
|---|---|---|
| 事实 | `facts/snapshots/*.db` | `python3 scripts/q.py <S-ID> "SQL"` |
| 规则 | `CLAUDE.md`/`AGENTS.md` + `knowledge/rules/` + `facts/koujing/` | 开工前全量读 |
| 任务 | `questions/questions.md` | 十问逐个答 |
| 产出 | `briefs/<季>/` | 过 `scripts/check_brief.py` 才算数 |

**任何"能读文件 + 能执行命令"的 agent 型 AI 都能运行本仓库**，不绑定引擎。

## 1. 环境要求（最小）

- 任意一台 Linux/macOS/Windows 机器
- python3（脚本只用标准库，无需装任何包）
- 一个 agent 形态的 AI CLI（能读写文件、执行命令），如 Claude Code、Codex CLI 或等价物 + 其模型账号
- 注意：答题会把业务数据发给所选模型的服务商，请走公司批准的通道

## 2. 每周数据例行（唯一必须的人肉动作）

1. 从平台后台导出 CSV → 放 `data/inbox/<来源>/`（UTF-8，首行列名）
2. `python3 scripts/snapshot.py --freeze`
3. 记下打印的快照 ID（如 `S-20260907`），本季答题都引用它

## 3. 企划季答题（具体指令）

在**仓库根目录**启动 agent，输入（照抄即可）：

> 先完整读 CLAUDE.md 和 knowledge/rules/ 全部规则卡。然后按 questions/questions.md 的 Q2 答题，
> 数据只用快照 S-XXXXXXXX（用 scripts/q.py 查），产出写到 briefs/<季>/q02-调换稳杀.md，
> 写完自己跑 python3 scripts/check_brief.py，有违规就改到通过。

- PM 只看 `briefs/`（md 可直接转飞书文档发群）
- PM 追问（"这个数怎么算的/换个口径/给我明细"）在同一会话里继续问，agent 现查快照回答

## 4. 三种接入形态（按团队能力选）

- **A. 终端形态（推荐起步，零开发）**：团队里一个会用命令行的人按 §2/§3 操作，PM 只消费产出。
- **B. 飞书/IM bot 形态（PM 完全不碰终端）**：加一层消息桥——飞书群 @bot → 后台起 agent CLI 跑本仓库 → 回消息。有开发量，等 A 形态跑顺、确有需求再做。
- **C. 纯聊天框（网页对话类，无执行能力）**：**运行不了产线**——查不了快照、跑不了闸。只能把 briefs/ 简报和规则/口径当材料贴进去做问答。不要尝试用聊天框跑产线。

## 5. 换引擎/换模型要动什么

几乎不动：规则入口双份（CLAUDE.md=Claude Code 自动读；AGENTS.md=Codex 系约定，内容指向前者）；脚本零厂商依赖。模型好坏只影响简报质量，正确性由闸门兜底（快照引用、check_brief、口径）。

新引擎接入验收三条：① 能用 q.py 查到快照数据；② 产出能过 check_brief；③ 简报每个数字带 [S- 引用。三条过 = 接入成功。
