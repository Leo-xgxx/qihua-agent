# 设计：AI 品类企划系统

## 0. 立场（两个判断）

1. **AI 的位置不是「写那份 46 页企划 PPT」，而是把「数据 → 证据 → 机会 → 候选策略 → 事后验证」整条链自动化。**
   PPT 是给评审会看的叙事外壳；工作的本体是回答十几个固定的决策问题。按章节组织工作（看复盘/看大盘/看市场…）是给人读的方式，按决策问题组织才是给决策用的方式。
2. **最贵的两个痛点——找数耗人力、需求验证薄弱——靠「方法论 SOP 教新人」解决不了，靠数据工程 + AI 能解决。**
   功夫的 80% 在事实层，不在提示词。喂进去的数是散的、无口径的，出来的就是「看起来像企划案的文本」，把老毛病自动化放大。

## 1. 四层结构（能少则少）

### ① 事实层（成败在此）
三类数据每周导入一个库，企划取数一律用冻结快照（带 ID，可复算）：
- 内部：SKU 级净销/退货/客诉/毛利/拉新/库存、直播场次、页面转化
- 外部：平台分价格带份额、榜单、搜索词、竞品 SKU 明细与评论
- 用户：问卷、评论原声、客服与退货原因记录

AI 在这层干它真正有比较优势的活：**把非结构化市场信息变成可查询的结构化事实**——竞品商品页/评论批量打标（版型、面料成分、功能卖点、价格）、差评聚类、退货原因编码。这些以前没人力做全量，现在能做了。
口径手册代码化：每个指标一个定义 + 计算方式，版本化（facts/koujing/）。

### ② 知识层（刻意做小）
不是方法论文档，是少量规则卡：一条被验证的判断规则 + 证据 + 适用边界 + 失效条件。
常态入口只有两个——评审会拍板、上季预测被验证（冷启动种子卡例外，标「历史萃取·待确认」，首评转正或删）；每季新增 ≤10 张，过期即删。
旧企划里被验证的东西（爆品判定指标阈值、价格带防守/进攻/探索三区）收进来当卡；46 页的章节结构不收。

### ③ 产出层（固定决策问题清单）
企划季启动，AI 对每个问题跑一遍，产出统一格式的一页简报。清单见 questions/questions.md（十问）。

### ④ 交付层
给 PM 的不是静态 PPT，是四样东西（见 §3）。

## 2. 「AI 做策略」这一步的具体做法

策略 = 机会 × 打法 × 资源承诺。AI 不自由发挥，走三步：
1. 从机会清单出发，每个机会生成 2–3 个候选打法（**含「不做」选项**）；
2. 每个候选强制填六字段：目标金额（附测算公式）/ 可证伪的前提假设 / 资源要价 / 主要风险 / 验证方式（小批量多少件、看什么指标、多久判定）/ 定价与价格带落位；
3. AI 先自己做反方论证——主动找证据反驳自己：历史同类打法的失败记录、假设最薄弱的一环。

全系统最关键的一条纪律：**每条被采纳的策略必须带一个可检验的预测**。
例：「直筒版上市 8 周内拿到该系列销量 20%±5%，否则停止追单」。
这一条同时买到三样东西：策略从形容词变成数字；下季复盘可全自动生成；预测被验证的规律自动沉淀成规则卡。闭环靠它转。

## 3. PM 按季拿到的四样东西

1. **季启动包**：十问各一页简报 + 老品调/换/稳/杀初稿 + 机会清单。PM 的工作从「做分析」变成「审结论、做取舍」。
2. **策略候选工作台**：候选打法卡（六字段齐全），PM 删改选择后进评审。
3. **一键渲染评审稿**：评审要 PPT 就渲染成 PPT，含溯源附录；评审的否决与质询记录回收，进下季知识层。
4. **随时追问**：对任何结论可以问「这个数怎么算的 / 换口径看看 / 给我明细」，AI 基于同一快照回答——这才是消灭「重复找数」的真解法。

一页简报示意（**数字为编造占位**）：

> **Q3：400–500 价格带要不要进攻？**
> 结论：进攻，但只投一个 IP 试。该带体量 X 亿 [S-xxxx 大盘份额表]，我份额 1.2%；流出用户 43% 去了某竞品同带，其好评前三 = 免烫/品牌/版型 [S-xxxx 评论表, N=2.1万]。
> 反方：我品在该带历史两次尝试均未过 500 件/月；品牌力短板短期补不上。
> 待验证假设：目标人群对免烫的支付意愿 ≥ 通勤人群。验证：先锋款 3000 件、8 周、看拉新与退货。
> 置信度：中。缺口：天猫该带数据未接入。

## 4. 纪律（fail closed，全部是机器可查的正确性闸）

- 简报里每个数字必须带快照引用，渲染前机器校验，缺引用不出稿；
- 样本不足的结论自动降级为「线索」，线索不允许被策略卡引用为依据；
- 数据缺口就写「不知道 + 缺什么」，禁止补写；
- 立项与订货金额必须人签，AI 只能建议。分析、初稿、追问全自动，不设人为吞吐上限。

## 5. 落地路线

见 docs/roadmap.md（三步：事实层+两问题 → 外部数据+机会清单 → 预测闭环）。

**明确不建**：多 agent 编排、自动评分系统、自动订货、审批流。一个模型 + sqlite + 固定问题清单就够；复杂度只允许出现在事实层的数据质量上。

## 6. 与「旧方法论萃取」路线的关系

萃取路线是「把人的老经验整理成 SOP 教给下一个人」；本系统是「把事实层和闭环建给 AI，AI 把分析做掉，人只保留取舍与拍板」。
老经验不浪费——被验证的判断规则进知识层规则卡；五段式章节骨架只在渲染评审稿时当模板。
不直接把历史 PPT 喂给 AI 仿写下一季的原因：产出会「像」企划案，但数字无源、假设未验，正是把老毛病自动化放大。
